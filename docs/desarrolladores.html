Arquitectura

Cómo está hecho Rukes: qué hace cada crate, qué pasa entre que pulsas una tecla y ves un resultado, y cómo ampliarlo.

Rukes es un ejecutable nativo de Windows en Rust (edición 2024). La interfaz usa iced 0.14 con el renderizador por software tiny-skia; la concurrencia, hilos y canales (crossbeam), sin runtime async. Los plugins integrados son código Rust en el mismo proceso; los externos, procesos aparte que hablan JSON.

┌──────────────────────────────┐ teclado / ratón ─▶ │ rukes-ui (iced: State, │ ◀── UiEvent (canal) ──┐ │ Message, update, view) │ │ └──────────────┬───────────────┘ │ │ trait Host │ ┌──────────────▼───────────────┐ │ │ rukes-app (Host, bandeja, │── ConfigWatcher ──────┤ │ atajos, triggers, ajustes) │── tray / hotkeys ─────┘ └──────┬──────────────┬────────┘ │ │ ┌─────────────▼───┐ ┌──────▼──────────┐ ┌─────────────────┐ │ rukes-core │ │ rukes-config │ │ rukes-platform │ │ Engine, pool, │ │ schema, temas, │ │ Win32: ventanas,│ │ ranking, i18n │ │ watch, edición │ │ shell, iconos… │ └───────┬─────────┘ └─────────────────┘ └─────────────────┘ │ Vec<Arc<dyn Plugin>> ┌────────────────┼─────────────────────┐ ┌────▼─────────┐ ┌────▼──────────┐ ┌────────▼───────┐ │rukes-plugins │ │ rukes-script │ │ externos (NDJSON│ │apps, calc, │ │ scripts, Rhai │ │ por stdin/stdout│ │files, http… │ │ │ │ en otro proceso)│ └──────────────┘ └───────────────┘ └─────────────────┘

Arranque

crates/rukes-app/src/main.rs, en orden:

  1. Opciones de línea de órdenes: --schema <archivo> escribe el JSON Schema; --export / --import copian la configuración. Terminan sin abrir la ventana.
  2. Rutas (rukes_config::paths): %APPDATA%\Rukes y %LOCALAPPDATA%\Rukes, o data\ si existe portable.txt.
  3. Logs (logging.rs): tracing a archivo rotado; RUKES_LOG fija el nivel.
  4. Instancia única (instance::acquire): si ya hay una, le pide que se muestre y sale.
  5. Configuración: crea config.toml comentado si no existe, lo carga, escribe config.schema.json, carga el idioma y el tema.
  6. Host: crea el Engine (pool con tantos hilos como núcleos, con tope), carga la frecency y llama a install_plugins.
  7. Vigilantes: ConfigWatcher sobre config.toml y DirWatcher sobre themes, lang, scripts, workflows y plugins. Un cambio recarga solo lo afectado.
  8. Bandeja, atajo global, atajos propios y triggers.
  9. rukes_ui::run(host, ui_rx, ui_config): bucle de iced en el hilo principal hasta salir. Al salir se guarda la frecency y se cierran los plugins externos.

Decisiones y reglas

Las decisiones de arquitectura están en docs/decisions/ (ADR):

ADRDecisión
0001iced + tiny-skia: binario pequeño, sin GPU obligatoria, arranque rápido.
0002Edición 2024 y lints estrictos: unwrap y expect prohibidos fuera de tests; #![forbid(unsafe_code)] salvo en rukes-platform; clippy -D warnings.
0003Hilos + crossbeam, sin tokio. Cada consulta tiene QueryId y CancelToken; una nueva cancela la anterior.
0004Estado en JSON versionado con escritura atómica (archivo temporal + rename).

Perfil release: lto = "fat", codegen-units = 1, panic = "unwind" (para que catch_unwind aísle el pánico de un plugin).

Con los mutex se usa siempre .lock().unwrap_or_else(|p| p.into_inner()): un pánico en otro hilo no envenena el resto de la aplicación.

Flujo de una consulta

tecla ─▶ Message::Input(texto) ─▶ host.query(texto, sink) ─▶ Engine::query │ ┌──────────────────────────────────────────────────────┘ │ 1. cancela el CancelToken de la consulta anterior │ 2. QueryId nuevo │ 3. route(plugins, texto) → [Route { plugin, text, targeted, boost }] │ 4. un job por ruta al pool ▼ hilo del pool: catch_unwind(|| plugin.query(&Query, &cancel, &mut |items| …)) │ cada vez que el plugin llama a sink(items): │ · rellena plugin_id, alias_match │ · score = ranking::final_score(fuzzy, frecency, alias, priority) │ · envía QueryBatch { id, items } por el Sink ▼ Host → UiEvent::Batch ─▶ rukes-ui: si batch.id == consulta actual ranking::merge(lista, items, max) → nueva vista
  • Los plugins pueden llamar a sink varias veces (resultados incrementales: los archivos llegan por tandas). merge sustituye duplicados por (plugin_id, id) y mantiene la lista ordenada.
  • Un plugin lento no bloquea a los demás: cada uno es un job independiente.
  • Un pánico dentro de query se captura, se registra en el log y no tumba el pool.
  • La UI descarta lotes de consultas viejas comparando el QueryId.

Enrutado

engine.rs::route decide qué plugins reciben la consulta y con qué texto:

  1. Prefijo: si el texto empieza por el prefix de algún plugin, va solo a ese, sin el prefijo. Gana el más largo (f: antes que f).
  2. Palabra clave + espacio: si empieza por una de sus keywords seguida de un espacio, va solo a ese plugin (g rust → web con «rust»). Las palabras clave pueden tener varias palabras (gh issue) y gana la más larga.
  3. Global: si no, va a todos los plugins con global = true, con targeted = false.
  4. list_on_keyword: si el texto es exactamente una palabra clave (clip sin espacio), además de la búsqueda global ese plugin recibe una consulta vacía dirigida y su lista sale arriba (boost).
// Query que recibe el plugin
pub struct Query {
    pub id: QueryId,     // para descartar resultados viejos
    pub raw: String,     // lo que escribió el usuario
    pub text: String,    // sin prefijo ni palabra clave, recortado
    pub targeted: bool,  // true si se usó su prefijo o palabra clave
}

Puntuación y frecency

crates/rukes-core/src/ranking.rs:

pub const ALIAS_BONUS: f32 = 1.0;
const QUERY_FRECENCY_SHARE: f32 = 0.6;

pub fn final_score(i: ScoreInput, frecency_weight: f32) -> f32 {
    let w = frecency_weight.clamp(0.0, 1.0);
    let frecency =
        i.item_frecency * (1.0 - QUERY_FRECENCY_SHARE) + i.query_frecency * QUERY_FRECENCY_SHARE;
    let alias = if i.alias_match { ALIAS_BONUS } else { 0.0 };
    i.fuzzy * (1.0 - w) + frecency * w + alias + i.priority
}
  • fuzzy (0..1): lo pone el plugin, normalmente con rukes_core::Fuzzy (envoltorio de nucleo-matcher).
  • Frecency (frecency.rs): cada vez que eliges un resultado se suma 1 a su entrada general y a la de esa consulta normalizada; el valor decae exponencialmente con una vida media configurable (value · 0.5^(Δt / half_life)) y se normaliza a 0..1.
  • Alias: si el texto coincide exactamente con un alias del resultado, +1.
  • Prioridad del plugin (−1..1, en config.toml).
  • Empates: título (sin mayúsculas), luego plugin_id, luego id; así la lista no «baila» entre pulsaciones.

Ejecutar una acción

Al pulsar Enter (o un atajo, o un botón de la fila) la UI llama a host.execute(item, action_id) → Engine::execute, que busca el plugin por item.plugin_id, apunta la elección en la frecency y llama a plugin.execute(item, action) dentro de catch_unwind. El resultado es un ActionOutcome:

VarianteQué hace la UI
HideOculta la ventana (según hide_after_action).
KeepOpenNo hace nada; vuelve a lanzar la consulta para refrescar.
ReplaceQuery(String)Escribe ese texto en la búsqueda.
Notify(String)Muestra un aviso breve y sigue abierta.
ShowResults(Vec<ResultItem>)Sustituye la lista (submenús, confirmaciones). El motor rellena plugin_id.
Paste { text, cursor_left, restore }Oculta, devuelve el foco a la ventana anterior, pega con Ctrl+V, pulsa ← cursor_left veces y, si restore, repone el portapapeles anterior.
OpenSettingsAbre el panel de ajustes.
OpenHttp { form, send }Abre el mini Postman con esa petición; si send, la envía.

Las acciones que terminan en segundo plano (un script con output = launcher) devuelven un resultado provisional «Ejecutando…» y luego el host envía UiEvent::Results { replaces, items } para sustituirlo.

El trait Plugin

crates/rukes-core/src/plugin.rs. Todo plugin integrado lo implementa; los externos y los scripts también, a través de un adaptador.

pub trait Plugin: Send + Sync {
    /// Id, nombre, prefijo, palabras clave, prioridad, global, list_on_keyword.
    fn metadata(&self) -> PluginMetadata;

    /// Se ejecuta en un hilo del pool, quizá en paralelo para consultas distintas.
    /// Debe mirar `cancel` en bucles largos y entregar con `sink` (puede llamarlo varias veces).
    fn query(&self, query: &Query, cancel: &CancelToken, sink: &mut dyn FnMut(Vec<ResultItem>));

    /// Ejecuta la acción `action` sobre un resultado suyo.
    fn execute(&self, item: &ResultItem, action: &str) -> Result<ActionOutcome, PluginError>;

    /// Reconstruye índices en segundo plano (comando «recargar»). Opcional.
    fn refresh(&self) {}

    /// Ayuda de «help <id>». Por defecto, la sección [usage.<id>] de los idiomas.
    fn help(&self) -> Option<PluginHelp> { PluginHelp::from_i18n(&self.metadata().id) }

    /// Comandos sin interfaz que acepta `call`. Opcional.
    fn commands(&self) -> Vec<PluginCommand> { Vec::new() }

    /// Ejecuta un comando (JSON entra, JSON sale). Puede llamarse desde cualquier hilo.
    fn call(&self, command: &str, _args: &serde_json::Value)
        -> Result<serde_json::Value, PluginError> {
        Err(PluginError::UnknownCommand(command.into()))
    }
}

Escribir un plugin integrado

Ejemplo completo: un plugin dado que lanza dados (dado 2d6). Va en crates/rukes-plugins/src/dice.rs.

//! Lanza dados: `dado`, `dado 20`, `dado 3d6`.

use rukes_core::i18n::{tr, trf};
use rukes_core::{
    Action, ActionId, ActionOutcome, CancelToken, Icon, Plugin, PluginError, PluginMetadata,
    Query, ResultItem,
};

/// Plugin de dados.
pub struct DicePlugin {
    /// Caras por defecto (de `config.toml`).
    pub faces: u32,
}

/// `"3d6"` → (3, 6); `"20"` → (1, 20); vacío → (1, faces).
fn parse(text: &str, faces: u32) -> Option<(u32, u32)> {
    let t = text.trim().to_lowercase();
    if t.is_empty() {
        return Some((1, faces));
    }
    let (n, f) = match t.split_once('d') {
        Some((n, f)) => (if n.is_empty() { 1 } else { n.parse().ok()? }, f.parse().ok()?),
        None => (1, t.parse().ok()?),
    };
    ((1..=100).contains(&n) && (2..=1000).contains(&f)).then_some((n, f))
}

fn roll(n: u32, faces: u32) -> Vec<u32> {
    (0..n).map(|_| getrandom::u32().unwrap_or(0) % faces + 1).collect()
}

impl Plugin for DicePlugin {
    fn metadata(&self) -> PluginMetadata {
        PluginMetadata {
            id: "dice".into(),
            name: tr("dice.name").into(),
            prefix: None,
            keywords: vec!["dado".into(), "dice".into()],
            priority: 0.0,
            global: false,          // solo con su palabra clave
            list_on_keyword: true,  // «dado» sin espacio ya muestra el resultado
        }
    }

    fn query(&self, q: &Query, cancel: &CancelToken, sink: &mut dyn FnMut(Vec<ResultItem>)) {
        let Some((n, faces)) = parse(&q.text, self.faces) else {
            return; // nada que mostrar: no se llama a sink
        };
        if cancel.is_cancelled() {
            return;
        }
        let dice = roll(n, faces);
        let total: u32 = dice.iter().sum();
        let mut item = ResultItem::new(format!("{n}d{faces}"), total.to_string());
        item.subtitle = trf("dice.subtitle", &[("dice", &format!("{dice:?}"))]);
        item.icon = Icon::Named("generator".into());
        item.fuzzy = 1.0;
        item.payload = total.to_string();
        item.actions = vec![
            Action::new(ActionId::OPEN, tr("dice.again")),
            Action::new("copy", tr("action.copy")),
        ];
        sink(vec![item]);
    }

    fn execute(&self, item: &ResultItem, action: &str) -> Result<ActionOutcome, PluginError> {
        match action {
            // Enter: volver a lanzar (la consulta se repite y sale otro número).
            ActionId::OPEN => Ok(ActionOutcome::KeepOpen),
            // crate::util::copy copia al portapapeles y devuelve el aviso «Copiado».
            "copy" => crate::util::copy(&item.payload),
            other => Err(PluginError::UnsupportedAction(other.into())),
        }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn parses_dice_notation() {
        assert_eq!(parse("", 6), Some((1, 6)));
        assert_eq!(parse("20", 6), Some((1, 20)));
        assert_eq!(parse("3d6", 6), Some((3, 6)));
        assert_eq!(parse("d8", 6), Some((1, 8)));
        assert_eq!(parse("0d6", 6), None);
        assert_eq!(parse("hola", 6), None);
    }

    #[test]
    fn rolls_stay_in_range() {
        assert!(roll(50, 6).iter().all(|d| (1..=6).contains(d)));
    }
}

Buenas prácticas

  • query debe ser rápido. Indexa en refresh o en un hilo propio y consulta el índice en memoria. Si haces E/S, comprueba cancel.is_cancelled() a menudo.
  • No llames a sink si no hay nada. Una lista vacía no hace daño, pero ahorra trabajo a la UI.
  • Ids estables: si el id cambia en cada consulta, la frecency no aprende.
  • Textos con tr/trf, nunca literales en la interfaz.
  • Errores: devuelve PluginError; la UI los muestra como aviso. Nada de unwrap.
  • Si el plugin necesita algo del host (ajustes, el motor), recíbelo en el constructor (Arc, Weak, una clausura) en vez de usar globales.

Registrarlo

Un plugin integrado toca seis sitios. Siguiendo el ejemplo de dice:

1. Exportar el módulo

pub mod dice;

2. Su sección en el esquema

/// Dados (`dado 3d6`).
#[derive(Debug, Clone, Serialize, Deserialize, JsonSchema, PartialEq)]
#[serde(default, deny_unknown_fields)]
pub struct Dice {
    /// Activar el plugin.
    pub enabled: bool,
    /// Caras por defecto.
    pub faces: u32,
}

impl Default for Dice {
    fn default() -> Self {
        Self { enabled: true, faces: 6 }
    }
}

// …y en `struct Plugins`:
pub dice: Dice,

Los comentarios /// se convierten en las descripciones del JSON Schema (el autocompletado de VS Code).

3. La configuración por defecto comentada

# Dados: «dado», «dado 20», «dado 3d6».
[plugins.dice]
enabled = true
faces = 6

El test default_template_parses_to_defaults compara este archivo con Config::default(): si no coinciden, falla.

4. Instalarlo en el host

if config.plugins.dice.enabled {
    plugins.push(Arc::new(rukes_plugins::dice::DicePlugin {
        faces: config.plugins.dice.faces,
    }));
}

install_plugins se vuelve a ejecutar cada vez que cambia la configuración, así que activar o desactivar el plugin no necesita reiniciar.

5. El interruptor en los ajustes

// clave con puntos, clave i18n del nombre, clave i18n de la ayuda ("" = sin ayuda), valor
toggle("plugins.dice.enabled", "dice.name", "", c.plugins.dice.enabled),

El test form_reflects_the_config_and_every_key_exists comprueba que cada clave del formulario existe en config.toml.

6. Textos y ayuda

[dice]
name = "Dados"
subtitle = "Tiradas: {dice} · Enter vuelve a lanzar"
again = "Lanzar otra vez"

[usage.dice]
summary = "Lanza dados con notación de rol"
ex1 = "dado | Un dado de 6 caras"
ex2 = "dado 20 | Un dado de 20 caras"
ex3 = "dado 3d6 | Tres dados de 6 caras y su suma"
tip1 = "Las caras por defecto se cambian en [plugins.dice] faces"

Lo mismo en en.toml. help dado ya mostrará la ayuda (la genera PluginHelp::from_i18n) y, si quieres, añade "dice" a los ids de la leyenda en hints.rs.

Comandos entre plugins

Un plugin expone comandos sin interfaz implementando commands y call. Otros plugins y la API de Rhai los llaman con Engine::call(plugin_id, comando, args), que busca el plugin, envuelve la llamada en catch_unwind y devuelve Result<serde_json::Value, PluginError>. Engine::commands() lista (plugin_id, PluginCommand) de todos.

impl Plugin for DicePlugin {
    // …
    fn commands(&self) -> Vec<PluginCommand> {
        vec![PluginCommand::new("roll", "{n, faces} → {dice: [..], total}")]
    }

    fn call(&self, command: &str, args: &serde_json::Value)
        -> Result<serde_json::Value, PluginError> {
        match command {
            "roll" => {
                let n = args["n"].as_u64().unwrap_or(1) as u32;
                let faces = args["faces"].as_u64().unwrap_or(u64::from(self.faces)) as u32;
                if !(1..=100).contains(&n) || !(2..=1000).contains(&faces) {
                    return Err(PluginError::BadArgs("n 1..100, faces 2..1000".into()));
                }
                let dice = roll(n, faces);
                let total: u32 = dice.iter().sum();
                Ok(serde_json::json!({ "dice": dice, "total": total }))
            }
            other => Err(PluginError::UnknownCommand(other.into())),
        }
    }
}
let r = plugin_call("dice", "roll", #{ n: 3, faces: 6 });
print(`Total: ${r.total}`);

Los comandos que ya existen (notes, todo, remind) están en la guía de usuario. call se puede invocar desde cualquier hilo: protege el estado compartido con un Mutex.

Ciclo de una consulta externa

  1. Primera consulta: arranca el proceso y envía initialize (espera hasta 5 s).
  2. Envía query con un id de petición y el query_id del motor.
  3. Espera la respuesta con recv_timeout en tramos cortos, mirando el CancelToken: si el usuario sigue escribiendo, envía cancel y deja de esperar (no cuenta como fallo).
  4. Las notificaciones results con ese query_id se entregan a sink al llegar.
  5. Timeout (2 s), proceso muerto o JSON ilegible: fallo. Tres seguidos → estado «desactivado» hasta recargar o reiniciar desde plugins. Un éxito pone el contador a cero.

El protocolo completo, con todos los campos, está en docs/plugin-protocol.md y resumido en la guía de usuario. Las plantillas que usa nuevo plugin están en crates/rukes-app/templates/ (plugin.py, plugin.js, plugin.ps1) y se incrustan con include_str! en create_plugin.rs.

Ejecución de un script

Enter ─▶ ScriptsPlugin::execute │ args::parse(texto tras el alias, cabecera) ─▶ error «falta title» si es required │ env = RUKES_QUERY, RUKES_ARG_*, RUKES_CLIPBOARD, RUKES_SELECTED_FILE(S), … │ runs.start(script) → id de ejecución (para «logs» y cancelar) ▼ hilo nuevo: .rhai → rhai_api::run(Input { source, query, args, env, deadline, cancel, … }) otro → proc::run(intérprete + archivo + args, env, cwd, timeout, job) │ ▼ según @rukes.output notification → notify(última línea) · clipboard → set_text · terminal → ventana visible launcher → filter::parse(salida) → UiEvent::Results · silent → nada runs.finish(id, código, salida, errores)

Los scripts con hotkey se registran como atajos globales con Target::Script; los de filter = true se ejecutan en query en vez de en execute (con un timeout corto y cancelación).

Sandbox de Rhai

rhai_api::engine(input, out) crea un rhai::Engine por ejecución:

let mut e = Engine::new();
e.set_module_resolver(rhai::module_resolvers::DummyModuleResolver::new()); // sin import
e.disable_symbol("eval");
e.set_max_call_levels(64);
e.set_max_expr_depths(64, 32);
e.set_max_string_size(16 * 1024 * 1024);
e.set_max_array_size(1_000_000);
e.set_max_map_size(100_000);
// Cada 512 operaciones: ¿pasó el deadline o se canceló? → se detiene el script.
e.on_progress(move |ops| (ops % 512 == 0 && l.stop()).then_some(Dynamic::UNIT));
e.on_print(/* añade a la salida */);
e.on_debug(/* añade "[debug línea:col] …" */);
  • No hay acceso a archivos: Rhai no trae funciones de E/S y no se registran.
  • query, args, selected_file y active_window se insertan en el Scope como constantes.
  • Las funciones que bloquean (sleep, run, http*) miran Limits::check() antes y durante: el timeout y el botón de cancelar de logs las cortan. run usa el mismo Job Object que los scripts normales.
  • http solo acepta http:// y https://, limita a 30 s y 8 MB (usa rukes_platform::http).
  • plugin_call, note_add, todo_add y remind usan Input::engine (Weak<Engine>) → Engine::call. Los valores se convierten de Dynamic a serde_json::Value y vuelta.
  • El valor final: si es una lista de mapas con title se convierte en resultados; si es texto o número se añade a la salida.

Añadir una función a Rhai

// En rhai_api::engine, junto a las demás:
e.register_fn("upper_first", |s: &str| -> String {
    let mut c = s.chars();
    match c.next() {
        Some(f) => f.to_uppercase().chain(c).collect(),
        None => String::new(),
    }
});

// Si puede fallar, devuelve Result y usa `err(...)` para un error legible:
e.register_fn("read_env_or", |name: &str, default: &str| -> Result<String, Box<EvalAltResult>> {
    Ok(std::env::var(name).unwrap_or_else(|_| default.to_owned()))
});

Después: un test en el módulo tests de rhai_api.rs (ejecutan código Rhai real con run), y una fila en la tabla de la API de la guía de usuario.

Workflows

crates/rukes-plugins/src/workflows/:

  • mod.rs: tipos (Workflow, Step, WindowSpec, Trigger, Target) y la carga de los .toml de la carpeta, con los ejemplos de la primera vez. Los errores se notifican con archivo y línea.
  • plugin.rs: el impl Plugin (buscar por nombre o alias, workflows, triggers, detalle con los pasos en Ctrl+P).
  • run.rs: ejecuta los pasos en orden en un hilo propio.
  • triggers.rs: el planificador.

Colocar una ventana

  1. Antes de abrir la app se apuntan las ventanas que ya existen.
  2. Se lanza con shell::launch (con runas si admin).
  3. Se espera (hasta wait) una ventana nueva visible del proceso, o una cuyo título o ejecutable contenga title (útil para apps de una sola instancia que reutilizan otro proceso).
  4. Se calcula el rectángulo en el área de trabajo del monitor (monitor::list, ordenados: principal primero y luego por x) a partir de snap o de x/y/width/height (píxeles o %), y se aplica con SetWindowPos, compensando el borde invisible de DWM.

Triggers y atajos

triggers.rs corre en un hilo que duerme hasta el próximo disparo:

const STARTUP_DELAY: u64 = 5;        // s tras arrancar para startup/login
const LOGIN_WINDOW: u64 = 10 * 60;  // login solo si Windows lleva menos de esto encendido

// Próximo disparo de cada tipo:
When::At { hh, mm, days } => próximo HH:MM en un día permitido (hora local)
When::Every(d)            => último + d (mínimo 60 s)
When::Startup             => Some(now + STARTUP_DELAY)
When::Login               => (uptime < LOGIN_WINDOW).then_some(now + STARTUP_DELAY)
  • Al despertar ejecuta los vencidos y recalcula. Si se despierta mucho más tarde de la hora de un at (suspensión), registra «hora perdida» y no lo ejecuta: pasa al siguiente.
  • run se resuelve a un Target: workflow:x, script:x, o un nombre suelto (primero workflow, luego script).
  • Pausar desde la bandeja detiene el disparo (el hilo sigue para poder reanudar).
  • Al cambiar los archivos de workflows se reconstruye la lista.

Atajos globales

Host::refresh_hotkeys reúne los atajos de los workflows, de los scripts y el del mini Postman en un HotkeySet de Target (Workflow / Script / Http), descarta los repetidos o iguales al principal (y lo notifica) y los registra con RegisterHotKey en rukes_platform::hotkey. Al pulsar uno, Host::run_target lo ejecuta: Http muestra la ventana y envía UiEvent::OpenHttp.

Configuración

  • Esquema (schema.rs): structs con #[serde(default)]; cada sección implementa Default. deny_unknown_fields detecta erratas. Los comentarios /// van al JSON Schema con schemars.
  • Por defecto (default_config.toml): el archivo que se escribe en el primer arranque, comentado. Un test verifica que coincide con Config::default().
  • Errores: toml da línea y columna; se notifica y se sigue con la configuración anterior.
  • Vigilancia (watch.rs): notify con antirrebote; los editores que guardan con «renombrar y sustituir» también se detectan.
  • Edición (edit.rs): el panel de ajustes manda pares (clave con puntos, SettingValue); se aplican con toml_edit, que conserva comentarios, orden y formato. Solo se escriben los cambiados.
  • Aplicar: al recargar, Host compara y rehace lo necesario (install_plugins, idioma, tema → UiEvent::Config, atajos, triggers, arranque con Windows).

Temas y tokens

crates/rukes-config/src/theme.rs carga el tema en tres pasos:

  1. Resolver extends (recursivo, con detección de ciclos): primero los incluidos (BUILTIN, incrustados con include_str! desde themes/), luego la carpeta del usuario, que puede sobrescribirlos.
  2. Fusionar los campos del archivo sobre el tema base. Si el archivo cambia bg, fg, muted o accent y no fija los tokens que dependen de ellos, esos tokens se reinician para volver a derivarse (no se hereda una surface que no casa con el fondo nuevo).
  3. Derivar los que faltan:
TokenDerivación

Los nombres del archivo admiten alias (FileColors con #[serde(alias)]): bg, text, text_muted/text-muted, border, surface-hover, text-faint, accent-soft.

Recortes de texto

iced no corta con «…»; fit_chars(ancho, tamaño) estima cuántos caracteres caben (ancho medio por carácter) y ellipsis / ellipsis_middle recortan. Es una aproximación: con fuentes muy anchas puede sobrar o faltar algún carácter.

pub trait Host: Send + Sync + 'static {

    fn settings_form(&self) -> Option<SettingsForm> { None }
    fn save_settings(&self, _changes: &[(String, SettingValue)]) -> Result<(), String> { … }
    fn open_config_file(&self) {}

Las llamadas lentas (http_send, iconos) se hacen en Task::perform fuera del hilo de la UI. Los eventos del host llegan por un canal que iced escucha como Subscription (UiEvent).

Plan para portarlo

1. Una fachada en rukes-platform

Las funciones públicas de rukes-platform ya son la frontera correcta: el resto del código no ve tipos de Windows. Se mantienen esas firmas y se reparte la implementación por sistema:

  shell.rs          ← fachada: #[cfg] y reexporta
  sys/windows/…     ← el código de hoy, movido tal cual
  sys/linux/…
  sys/macos/…
// shell.rs
#[cfg(windows)]
pub use crate::sys::windows::shell::*;
#[cfg(target_os = "linux")]
pub use crate::sys::linux::shell::*;
#[cfg(target_os = "macos")]
pub use crate::sys::macos::shell::*;
# Cargo.toml de rukes-platform: el crate windows solo en Windows
[target.'cfg(windows)'.dependencies]
windows = { workspace = true, features = [ … ] }

[target.'cfg(target_os = "linux")'.dependencies]
# zbus, x11rb, …

[target.'cfg(target_os = "macos")'.dependencies]
# objc2, objc2-app-kit, core-graphics, …

PlatformError::Win32 pasa a ser una variante solo de Windows y se añade PlatformError::Unsupported(&'static str) para lo que un sistema no pueda hacer. Los plugins ya convierten los errores en un aviso en la ventana.

2. Primero que compile: stubs

Antes de implementar nada, cada módulo de Linux y macOS devuelve Err(Unsupported) o una lista vacía. Con eso la compilación ya pasa y se puede avanzar módulo a módulo con la app arrancando. En este paso se revisan también los #[cfg] de rukes-plugins y rukes-script que hoy suponen Windows (external/process.rs, files/index.rs, workflows/run.rs, proc.rs).

4. Lo que hay fuera de rukes-platform

  • Rutas (Paths::detect): en Linux ~/.config/rukes, ~/.local/state/rukes y ~/.cache/rukes (respetando las variables XDG_*); en macOS ~/Library/Application Support/Rukes, ~/Library/Caches/Rukes y ~/Library/Logs/Rukes. El modo portable no cambia.
  • UI: app.rs debe aceptar también RawWindowHandle::Xlib, Wayland y AppKit (o que window_ready reciba un tipo neutro). Hay que probar la posición anclada abajo y resize_keep_bottom, que hoy hace el host con la API de Windows.
  • Teclas: en macOS lo natural es ⌘ en lugar de Ctrl. En iced, modifiers.command() ya es ⌘ en macOS y Ctrl en el resto: se cambian los m.control() del launcher por m.command().
  • Scripts: sin cmd; .ps1 usa pwsh si existe; .sh con sh/bash, respetando el shebang (#!/usr/bin/env python3). Las plantillas añaden una de shell.
  • Plugins externos: el command de plugin.toml puede necesitar variantes por sistema (command.windows, command.linux…).
  • build.rs: llamar a embed-resource solo si CARGO_CFG_TARGET_OS == "windows".
  • Textos: «Explorador», «Iniciar con Windows»… pasan a claves que dependan del sistema o a textos neutros («gestor de archivos», «Iniciar con el sistema»).

5. Orden recomendado

  1. Que compile en los tres con stubs y CI en matriz (abajo), sin funcionalidad nueva.
  2. Mínimo usable: rutas, instancia única, atajo global, bandeja, ventana, apps con iconos, abrir archivos, calculadora, archivos y portapapeles. Con esto ya es un launcher.
  3. Paridad: ventanas, controles del sistema, pegar, fondos, inicio automático y cifrado del historial.
  4. Distribución en cada sistema.
Empieza por X11 en Linux. En Wayland no hay atajos globales, ni posición absoluta de ventanas, ni lista de ventanas de otras apps: son límites del protocolo, no de Rukes. La solución habitual (la de otros launchers) es que el usuario cree un atajo del escritorio que ejecute rukes --toggle.

CI con los tres sistemas

jobs:
  check:
    strategy:
      fail-fast: false
      matrix:
        os: [windows-latest, ubuntu-latest, macos-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: clippy, rustfmt
      - uses: Swatinem/rust-cache@v2
      - name: Dependencias de Linux
        if: runner.os == 'Linux'
        run: |
          sudo apt-get update
          sudo apt-get install -y libxkbcommon-dev libwayland-dev libx11-dev libxcursor-dev \
            libxrandr-dev libxi-dev libgtk-3-dev libayatana-appindicator3-dev libdbus-1-dev
      - run: cargo fmt --all --check
      - run: cargo clippy --workspace --all-targets -- -D warnings
      - run: cargo test --workspace
      - run: cargo build --release -p rukes-app

Mientras no existan los stubs, Linux y macOS darán errores de compilación en la matriz. Que se pongan en verde es la señal de que el paso 2 está terminado.

Probar sin cambiar de máquina

  • cargo check -p rukes-app --target x86_64-unknown-linux-gnu desde Windows (tras rustup target add x86_64-unknown-linux-gnu) comprueba tipos y #[cfg] sin enlazar: es lo más rápido para saber si los stubs cubren todo.
  • Linux: WSL2 con WSLg, o una máquina virtual con GNOME (para probar X11 y Wayland).
  • macOS: el runner macos-latest de GitHub para compilar y pasar los tests; para la interfaz hace falta un Mac.

Recetas

Añadir un ajuste

  1. Campo con /// en la struct de schema.rs y su valor en Default.
  2. La misma línea, comentada, en default_config.toml.
  3. Úsalo donde toque (en Host, en el plugin o en UiConfig si es de la interfaz).
  4. Si debe salir en el panel: una fila en settings_panel.rs (toggle, choice, slider, text…) con su clave con puntos, y su validación si hace falta.
  5. Textos en es.toml y en.toml.

Añadir un tema incluido

  1. themes/mi-tema.toml (con extends = "rukes-dark" si solo cambias colores).
  2. Añádelo a BUILTIN en rukes-config/src/theme.rs con include_str!.
  3. cargo test -p rukes-config: every_builtin_theme_loads lo valida.

Añadir un idioma

  1. Copia crates/rukes-core/lang/en.toml a fr.toml y tradúcelo.
  2. Regístralo en i18n.rs (lista de idiomas incrustados) y en la lista del ajuste language.
  3. El test de claves comprobará que no falta ninguna.

Añadir un atajo al launcher

  1. Si es una acción sobre la fila: una constante nueva en ActionId.
  2. En app.rs, en el manejador de teclado del modo búsqueda, asócialo a esa acción.
  3. Los plugins que la soporten la añaden a actions de sus resultados.
  4. Documéntalo en la leyenda (hints.rs), en la ayuda y en la tabla de atajos.

Añadir un paso de workflow

  1. Variante nueva en Step (workflows/mod.rs), con serde untagged por su clave.
  2. Su ejecución en run.rs y su descripción en el detalle (plugin.rs).
  3. Test de parseo y fila en la tabla de la guía.

Publicar una versión

El proceso completo está en docs/release.md: subir la versión en Cargo.toml, actualizar CHANGELOG.md, compilar en release, generar el instalador y el ZIP portable, firmar y publicar la release. Las mediciones de rendimiento de referencia están en docs/benchmarks.md.
